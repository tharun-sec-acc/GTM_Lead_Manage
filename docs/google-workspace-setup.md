# Legacy Google Workspace calendar setup (not used by the active meetings UI)

The active meetings screen now uses Microsoft 365. The Google calendar routes and stored records are retained for legacy compatibility; this setup guide is historical and is not the recommended connection path. The legacy organizer authorization and Calendar availability lookup remain. Google Meet creation, calendar invitations, Drive recordings/transcripts, OAuth Gmail sending and public booking confirmation are implemented in the meetings, email and booking modules (mock-tested only). Jira is not implemented.

1. In an approved Google Cloud project, enable the Google Calendar API and configure the OAuth consent screen. Add the test organizer as a test user where required. Create an OAuth **Web application** client and register exactly `http://localhost:8000/google/oauth/callback` as an authorized redirect URI. This app uses a server callback at that exact path. An OAuth JSON with an `"installed"` section is a Desktop/Installed client and is not compatible with this callback; use a downloaded JSON with a `"web"` section. Use the same `localhost` hostname throughout; a cookie set for `127.0.0.1` will not be available on `localhost`.
2. Privately copy the Web client’s `client_id` into `GOOGLE_CLIENT_ID` and its `client_secret` into `GOOGLE_CLIENT_SECRET` in the local `.env`. Also set `GOOGLE_WORKSPACE_ORGANIZER_EMAIL` and `GOOGLE_TOKEN_ENCRYPTION_KEY`. Generate a Fernet key locally with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` and keep it secret. Never paste OAuth client secrets, refresh tokens, or encryption keys into chat or commit them. Retain the Fernet key: changing it makes stored tokens unreadable.

   `GOOGLE_TOKEN_ENCRYPTION_KEY` is a separate application encryption key, not the Google OAuth client secret. Fernet uses it to encrypt the OAuth PKCE verifier temporarily and the organizer’s Google refresh token before storing either in PostgreSQL. The same key must be available to the API whenever it needs to encrypt or decrypt these values.

   The error `GOOGLE_TOKEN_ENCRYPTION_KEY must be a valid Fernet key` means the value currently loaded by the API is empty, malformed, or not a Fernet-generated key. Generate a new Fernet key with the command above and set the resulting single-line value after `GOOGLE_TOKEN_ENCRYPTION_KEY=` in the private `.env`; do not use the Google client ID or secret for this setting. If a Google connection or OAuth attempt already succeeded with a previous key, do not replace it casually: previously encrypted records cannot be decrypted with a different key, so reconnecting may be required.

   If a client secret has been exposed, revoke or rotate it in Google Cloud before using the integration, then update the private `.env` with the replacement. Do not reuse the exposed credential.
3. Keep `GOOGLE_REDIRECT_URI=http://localhost:8000/google/oauth/callback` only if maintaining an existing legacy connection. The current `/meetings` screen does not initiate Google authorization. The retained Google routes historically requested `openid`, `userinfo.email`, and `calendar.freebusy`, with offline access; only the matching verified organizer identity was accepted. An optional reconnect request also asked for `calendar.events.owned`; booking is now performed by the booking module, which creates a Google Calendar event with a Meet link.
4. The legacy disconnect route revokes the token and removes the stored encrypted refresh token. Meet and Drive artifact operations require the corresponding scopes and policy review; the email/meeting OAuth flow requests the scopes it needs, so reconnect the account after changing them.

Google Workspace administrator policies and account/edition permissions may restrict the integration. No real Google account has been tested. Refresh tokens are encrypted at rest and the application now requires sign-in; an organization-scoped OAuth connection is still usable by any member with the right role. Do not expose or forward any pilot ports.
